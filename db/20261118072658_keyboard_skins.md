# Keyboard skins catalog and equipped skin

**Applied:** 2026-11-17 23:26 PST (2026-11-18 07:26 UTC) to `BigWalkProject`
**Migration:** `20261118072658_keyboard_skins`
**Card:** [M7 account-profile — Keyboard skins](https://trello.com/c/6RXv5KoN/71-m7-account-profile-keyboard-skins)
**For:** Ramon (catalog and equipped skin, RLS) and Kevin (routes). Please check that this matches what you intended, or point me at your version if you already have one.

## Why

The client's Keyboard skins picker (`src/features/skins/`) saves the equipped skin in `localStorage` only, so a Member gets the default skin on a new device or browser. M7 needs the skin saved on the account, and unknown skin IDs rejected.

What the live database has today:

- `users.keyboard_styles (name varchar(50) primary key)` exists with 0 rows, RLS off, and no client grants. Nothing uses it.
- `feature/supabase-queries` `schema.sql` puts `keyboard_style` on `users.settings`, but the live `users.settings` is `account_id`, `prefs jsonb` and `updated_at` (used by `get_my_settings` / `save_my_settings`), so that column was never applied.
- `users.users` already holds the other cosmetic choice, `profile_pic`, so the equipped skin goes there.

## What changes

**`users.keyboard_styles`** (the catalog)
- Seeded with the four skins in `KEY_SKINS`: `classic`, `mint`, `wood`, `speckle`.
- RLS on, no policies, all privileges revoked from `public`, `anon` and `authenticated`. Clients read it only through `get_keyboard_skins`.

**`users.users.keyboard_style`** (the equipped skin)
- `varchar(50) not null default 'classic'`, foreign key to `users.keyboard_styles (name)`. A skin that isn't in the catalog can't be stored by any path.
- Existing rows (158) and new rows from `trigger_guest_user_copy` get `classic` from the default. The trigger doesn't need changing.
- No index on the column: the foreign key is only checked from that side on catalog deletes, and catalog rows should never be deleted (see **Adding or retiring a skin**).

**`public.get_keyboard_skins()` → `setof text`**
- The catalog's skin IDs, sorted by name. Security definer, `search_path = ''`, `authenticated` only (guests included).

**`public.get_my_keyboard_skin()` → `text`**
- The caller's equipped skin, or null if they have no `users.users` row. Same security as above.

**`public.equip_keyboard_skin(p_skin text)` → `void`**
- Saves the caller's equipped skin. Only ever updates the caller's own row (`auth.uid()`); there is no account parameter.
- Errors:

| Case | Error | Code |
|---|---|---|
| Not signed in | `not signed in` | `42501` |
| Guest (anonymous user) | `guests can only use the default keyboard skin` | `42501` |
| Skin not in the catalog | `unknown keyboard skin` | `22023` |
| Caller has no `users.users` row | `account not found` | `P0002` |

- Guests are rejected even for `classic`. Their row already has `classic`, and the client doesn't save for guests.

## Adding or retiring a skin

- **Adding:** insert the new ID into `users.keyboard_styles` when the client adds it to `KEY_SKINS`. Until then, `equip_keyboard_skin` rejects it.
- **Retiring:** keep the catalog row. Deleting it fails while any player has it equipped, and the client README already says retired IDs are never reused.

## Client

- `src/features/skins/keySkinSync.ts`: `loadKeySkin` reads `get_my_keyboard_skin()` when a Member signs in (from `KeySkinApplier`). `equipKeySkin` equips right away and, for Members, calls `equip_keyboard_skin`, one save at a time so the last pick wins.
- The account's skin replaces this device's at sign-in, except when the player picks a skin while it's loading. An ID the client doesn't know is ignored.
- A failed load or save keeps this device's skin and logs a warning. The client doesn't call `get_keyboard_skins()`; it's there for tools and tests.
- `localStorage` stays as this device's cache, and is all Guests use.

## Verified

**On `BigWalkProject` after applying**, as real accounts with `authenticated` / `anon` roles, inside one block that was rolled back (no player's skin was changed):

| Member equips `lava` | Rejected, `22023` |
| Member selects from `users.keyboard_styles` directly | Denied, `42501` |
| `get_keyboard_skins()` | `classic, mint, speckle, wood` |

## Roll back

```sql
drop function public.equip_keyboard_skin(text);
drop function public.get_my_keyboard_skin();
drop function public.get_keyboard_skins();
alter table users.users drop column keyboard_style;
delete from users.keyboard_styles where name in ('classic', 'mint', 'wood', 'speckle');
alter table users.keyboard_styles disable row level security;
```

## SQL

```sql
insert into users.keyboard_styles (name)
values ('classic'), ('mint'), ('wood'), ('speckle');

alter table users.keyboard_styles enable row level security;
revoke all on users.keyboard_styles from public, anon, authenticated;

alter table users.users
  add column keyboard_style varchar(50) not null default 'classic'
  constraint users_keyboard_style_fkey references users.keyboard_styles (name);

create function public.get_keyboard_skins()
returns setof text
language sql
stable
security definer
set search_path = ''
as $$
  select k.name::text from users.keyboard_styles k order by k.name;
$$;

revoke all on function public.get_keyboard_skins() from public, anon;
grant execute on function public.get_keyboard_skins() to authenticated;

create function public.get_my_keyboard_skin()
returns text
language sql
stable
security definer
set search_path = ''
as $$
  select u.keyboard_style::text from users.users u where u.account_id = auth.uid();
$$;

revoke all on function public.get_my_keyboard_skin() from public, anon;
grant execute on function public.get_my_keyboard_skin() to authenticated;

create function public.equip_keyboard_skin(p_skin text)
returns void
language plpgsql
security definer
set search_path = ''
as $$
begin
  if auth.uid() is null then
    raise exception 'not signed in' using errcode = '42501';
  end if;
  if coalesce((auth.jwt() ->> 'is_anonymous')::boolean, false) then
    raise exception 'guests can only use the default keyboard skin' using errcode = '42501';
  end if;
  if not exists (select 1 from users.keyboard_styles k where k.name = p_skin) then
    raise exception 'unknown keyboard skin' using errcode = '22023';
  end if;

  update users.users
     set keyboard_style = p_skin
   where account_id = auth.uid();

  if not found then
    raise exception 'account not found' using errcode = 'P0002';
  end if;
end;
$$;

revoke all on function public.equip_keyboard_skin(text) from public, anon;
grant execute on function public.equip_keyboard_skin(text) to authenticated;
```
